## 作品形式与建议

**建议先H5投稿，后续个人小程序原生实现。** 这是对当前代码和接入成本的判断，不是主办方保证接受或入围。

当天重新通过浏览器读取[官方比赛细则](https://www.yuque.com/shanxian/dfe94a/xzter263dyio4ge3?singleDoc)：作品形式包含网站、App、小程序等；提交可公开或经授权访问的URL，或ZIP；作品须能实际运行、可交互且体现AI价值，并在评审期间持续可访问。因此不必先完成正式支付宝小程序上架。ZIP上传入口当天没有再次核对，不能保证当前已开放。

[支付宝官方web-view文档](https://github.com/AlipayDocs/open-docs/blob/main/mini/component/基础组件/开放组件/web-view/web-view%20H5%20页面承载.md)明确不支持个人小程序使用。未来个人小程序需要原生页面及平台身份校验，不能把现有H5简单套壳。网页能在支付宝内置浏览器打开，也不代表它已成为小程序或被阿宝接入。

## 可以部署到哪里

| 位置 | 当前适用性 | 需要补充 |
| --- | --- | --- |
| 现有Sites | 已运行，源码与平台最匹配 | 评审授权/登录安排；国内手机能否访问未知。只开放网址不能消除ChatGPT身份依赖 |
| 自有Cloudflare Workers + D1 + R2 | 技术栈接近，可作为独立H5候选 | 自有账号、资源绑定、secret、身份适配、域名/部署检查；尚未独立部署或验证国内可用性 |
| 国内云托管 | 面向国内评审/后续用户的优先评估方向 | 自有账号、部署入口；把Worker数据库/对象存储和Sites身份适配到所选平台，再核对域名与当前接入要求。不能视为一键搬家 |
| GitHub Pages | 仅适合另做静态界面demo、说明页 | 无服务端模型secret、数据库及私密媒体后端；目前未启用，不能直接部署此全栈源码 |
| 支付宝小程序 | 后续个人路线 | 开放平台实名、创建AppID、核对服务类目/权限、开发者工具、原生界面、后端登录与媒体、体验版、真机/提审、正式发布 |

[GitHub官方文档](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)说明Pages是静态托管。[Cloudflare官方部署文档](https://developers.cloudflare.com/workers/platform/deploy-buttons/)说明Workers可配置数据库与存储等资源。上述平台能力不等于本项目已经完成迁移；不在未核验的情况下承诺免费额度、价格或国内可达性。

## 推荐下一轮H5实施顺序

1. 保留已同步的第6版作为基线。成功迭代先推GitHub并核对，再发布对应运行版本。
2. 确定评审可用的托管/访问入口。最快沿用Sites需授权且评审能登录；更稳妥面向国内的是独立H5托管并移除Sites身份依赖，需要提供已选云平台或现有部署入口，不需在聊天发送密钥。当前没有替用户采购或创建云账号。
3. demo使用虚构家庭与示例资料，允许浏览者体验“老人表达—家人查看—没看懂—重新表达”。实际调用DeepSeek建议时由服务端保存密钥、限额及回退；模拟收发明确标注，不暴露任何正式家庭资料。
4. 用新的访客环境检查打开、实际AI输入、异常回退、手机布局及完整示例流程。真人测试按用户决定暂缓；这一步验证运行和访问，不虚构老人效果。
5. 固定投稿版本和访问URL；整理简介、16:9封面、三分钟以内建议演示脚本及必要访问说明。视频是官方选填，建议展示AI原文保留、人工确认和“没看懂”纠错。当前封面1600×900及候选简介已完成。
6. 从[许愿池](https://render.alipay.com/p/yuyan/180022670000174287/index.html#/ideas)找到“解决孤独老年人的陪伴问题”，点击“帮TA实现”，核对关联愿望及作品URL，选择网站/H5（以表单实际选项为准），填写介绍与模型/工具来源，上传封面，提交后保存回执。此前已观察到该按钮进入愿望关联投稿入口；不能据此保证许愿者自动收到通知或立即体验。
7. 投稿后维持服务、模型额度和版本记录，再按评审/许愿用户反馈修正；真实家庭试用与目标用户理解观察另行推进。

第5/6步前的投稿运行入口仍待完成，代码和材料完成不等于投稿完成。只提交公开源码仓库地址，不能自动满足可交互体验要求。个人小程序后续再按当时开放平台规则实施。

## 仍然值得关注的产品问题

- AI从家人的短文字选择有限图卡，当前独特价值较窄。投稿需展示具体减少什么表达工作、何时会错、如何修正；不能把“接入模型”当作价值证明。
- 图卡对不识字者是否足够直观未知，熟悉照片可能更有帮助，须保留未理解回应。真人测试暂缓后，材料仍注明未验证。
- 收到/打开不等于理解或回复；没有后台推送，双方要主动打开页面。演示不得制造实时家属回应。
- 老人持续使用、家人沟通负担和孤独效果没有数据，投稿写探索性目标。
- 现有消息/媒体30天停止访问，物理清理依赖访问触发；正式用户服务需要继续落实清理和反馈处理责任。demo只用虚构资料。
