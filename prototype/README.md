# 邻里有伴移动端原型

这是“邻里有伴”参赛验证原型的本地全栈功能版，不是已上线养老服务。前端通过本地 Node.js 服务访问演示 API，状态按浏览器 Cookie session 保存在服务进程内，重启服务即清空；不要填入真实老人资料。

## 当前可演示

- 首次设置：姓名、年龄、帮助方式和兴趣偏好
- 首页四个生活动作入口：出去走走、给家里人说句话、帮我说清楚、报个平安
- 一级导航收敛为“今天 / 活动 / 家人 / 我的”；兴趣小组、陪伴和记录放入相关页面或“我的”
- 四条虚构活动卡：时间、地点、组织者、状态和演示标记
- “我想参加”→确认卡→本人确认/取消→本地演示回执
- 三个兴趣社群的本机加入意愿回执（不展示虚构成员数量）
- “我听不清，请打字”的预设文字卡流程，并显示一条标注为本机演示的家人回复
- 陪伴称呼和记忆内容的本机定制
- 报平安记录、通知记录和满员活动回退
- 一个不自动执行动作的 AI 候选意图演示
- 返回、取消、放大文字、满员活动、网络错误提示和模拟状态提示
- 暖绿、橙、蓝分工的生活化视觉系统、场景插画素材、活动图片缩略图、陪伴/报平安大图区域、四栏底部导航和 360/390/430 CSS px 适配

## 明确不包含

真实报名、真实消息、真实家属绑定、定位、持续轨迹、视频通话、手语识别、自动告警、医疗判断和数字伴侣。

## 本地运行

在项目根目录运行完整功能版：

    npm start

然后访问 http://127.0.0.1:4173/。

仅查看静态页面时，也可以直接打开 index.html；若浏览器限制本地文件行为，可启动静态服务器：

    python -m http.server 4173

然后访问 http://localhost:4173/prototype/。静态服务器不会提供本项目的 API 状态保存。

## API

- `GET /health`：读取服务健康状态
- `GET /api/state`：读取当前浏览器 session 的演示状态
- `POST /api/profile`：保存首次设置
- `POST /api/companion`：保存陪伴形象设置
- `POST /api/join-event`：记录活动参加意愿
- `POST /api/join-group`：记录加入兴趣小组意愿
- `POST /api/message`：生成本机文字卡记录
- `POST /api/checkin`：生成本机报平安记录
- `POST /api/assist`：返回规则化候选意图
- `POST /api/reset`：重置演示状态

## 投稿边界

当前实现可以展示前端、后端、状态流转和确认交互，但仍是本机模拟数据：不真实报名、不真实发消息、不读取真实定位、不绑定家属、不接入支付宝正式 API，不提供视频通话、手语自动识别、自动告警或持续监护。页面使用仓库内的轻量 SVG 场景插画作为视觉素材，图片只负责展示，文字、按钮和状态仍由页面交互控制。/api/assist 当前为本地规则建议，返回 provider: local-rule、fallback: true；投稿时应把这些限制和后续接入方向写明，不能把本地回执描述为真实服务结果。
